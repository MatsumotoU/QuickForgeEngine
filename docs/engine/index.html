ゲームエンジン / Windows

エンジンの使い方

QuickForgeEngineは、ゲームで使う機能を提供するエンジンと、それらを組み合わせてアプリケーションの起動・更新・終了を進めるフレームワークで構成されています。

概要

現在の実行環境はWindows向けです。アプリケーションの起動時にフレームワークが必要なシステムを用意し、ゲームプロジェクトのシーンとゲーム固有の処理を動かします。描画にはDirect3D 12を使用します。

フレームワークは、各機能を毎回アプリケーション側で個別に初期化・呼び出しする手間をまとめる土台です。ゲーム固有のルールや操作はゲーム側で実装します。

フレームワークの役割

WindowsEngineFramework と WindowsQuickForgeEngineSystems が、Windows版エンジンの共通システムを組み立てて管理します。ウィンドウや描画機能などの依存関係を考慮して初期化し、フレーム開始・終了の処理や終了時の後片付けも提供します。

その上で、アプリケーションはゲームモジュールを呼び出してゲーム固有の更新を行います。つまり、フレームワークがゲーム内容を自動で作るのではなく、共通部分の起動と進行を受け持ちます。

主な機能

  • ウィンドウ・描画: WindowsのゲームウィンドウとDirect3D 12による描画
  • 入力・GUI: キーボードやゲームパッドなどの入力、開発用GUI
  • シーン・エンティティ: シーンの読み込みと、エンティティ／コンポーネントの管理
  • スクリプト・音声: Luaスクリプトの実行と音声再生
  • アセット・アニメーション等: ゲームデータやモデルの読み込み、各種コンポーネントの処理

これらは別々のエンジン機能ですが、フレームワークが共通のシステムとしてまとめて扱います。

ゲームを動かす流れ

  1. フレームワークがウィンドウ、描画、入力、シーン管理などのシステムを初期化します。
  2. ゲームモジュールを読み込み、ゲーム独自のコンポーネントを登録します。
  3. ゲームプロジェクトのアセットを開き、開始シーンを読み込みます。
  4. 毎フレーム、入力や経過時間を受け取り、ゲームモジュールがゲーム固有の更新処理を行います。
  5. フレームワークが描画などの共通処理を進め、アプリケーション終了時にシステムを片付けます。

実装上は、起動時に CreateWindowsQuickForgeEngineSystems でシステムを作り、ループ中に BeginWindowsEngineFrame、ゲームモジュールの更新、描画処理、EndWindowsEngineFrame を呼びます。終了時は ShutdownWindowsQuickForgeEngineSystems を呼びます。

ゲームプロジェクト

ランタイムはゲームプロジェクトの project.json を選択して実行します。設定の start_scene が最初に読み込むシーンを指定し、ゲームデータはプロジェクトの assets 以下に配置します。

ゲーム固有のC++処理はゲームモジュールに、シーン・モデル・画像・音声・Luaスクリプトなどのデータはプロジェクトのアセットに置く構成です。Luaスクリプトの入口と主なAPIは、リポジトリ内の game-projects/sample/assets/scripts/README.md にまとめています。
