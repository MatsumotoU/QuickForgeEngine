# 敵との遭遇部屋

`EncounterRoomComponent` は ShootingGame の部屋用コンポーネントです。カメラの切り替えに使う `CameraRoomComponent` とは別に設定します。部屋の状態は実行中だけ保持され、シーンを読み直すと初期状態に戻ります。

1. 部屋の中心に空のエンティティを作り、`TransformComponent` と `EncounterRoomComponent` を付けます。`player` にはプレイヤーを指定し、`halfExtents` に入室判定の半分の大きさを設定します。範囲はワールド座標の各軸に沿い、部屋の回転・拡縮は適用されません。
2. 入口と出口に扉エンティティを配置し、閉じた状態の位置にします。移動を遮るために壁と同じコライダーを付け、`doors` にそれぞれ追加します。`openOffset` は閉位置から開位置までの移動量で、扉の親から見たローカル座標です。開いた扉が通路を塞がない値にしてください。
3. 事前配置する敵は `enemies` に追加します。入室時に生成する敵は `spawns` に追加し、`entityPath` に assets からの相対パス（例: `entities/enemy.entity`）、`offset` に部屋の中心からのワールド座標上の差分を指定します。両方を同じ部屋で使えます。
4. 入室判定の範囲は、プレイヤーが扉を通過しきってから内側に入るように設定します。開始前は扉が開き、入室で滑らかに閉じ、登録・生成された敵のエンティティがすべて削除されると開きます。`doorCloseDuration` で閉じるまでの秒数を設定でき、0 以下なら即座に閉じます。クリア後に再入室しても閉じません。

Scene Viewer の `Game Debug` をオンにすると、入室判定範囲をピンク、扉の閉位置をオレンジ、開位置を水色で表示し、白い線で移動方向を結びます。参照先が未設定・削除済みの扉は、部屋の中心に件数を表示します。扉の位置に表示する枠はコライダーの範囲です。コライダーがない場合は小さな枠を表示します。

コライダー・カメラ部屋・スプラインを含むデバッグ線は ImGui で映像に重ねて表示します。そのため、壁などに隠れている位置の線も見えます。

現在のゲームの衝突判定は扉の親子関係を考慮しないため、扉は親なしで配置してください。親がある場合、扉の見た目と衝突位置がずれることがあります。デバッグ枠は現在の衝突位置に合わせます。

空の部屋や宝箱だけの部屋には、このコンポーネントは不要です。ボス部屋でもボスを敵として登録できます。扉は 1 つの部屋だけに登録し、他の部屋と同じ扉を共有しないでください。

判定するのは敵のエンティティが削除されたかどうかです。`Enemy` タグと `StatusComponent` を持つ敵は HP が 0 になると削除され、全員消えると扉が開きます。生成するアセットの読み込みに失敗すると、全滅したと誤認しないよう扉は閉じたままになり、デバッグ時のログにエラーが出ます。存在しないプレイヤー・扉・事前配置の敵を指定した場合は、その部屋の処理を開始しません。
