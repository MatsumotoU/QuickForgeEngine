## 何を知りたかったか

QuickForgeEngineにプリコンパイル済みヘッダー（PCH）を導入すると、Runtimeと依存プロジェクトのビルド時間がどのように変わるかを知りたかった。クリーンリビルドと、共通ヘッダーを変更した後の差分ビルドをそれぞれ計測した。

## 分かったこと

2026年11月22日に、PCHあり・なしを各2回ずつ計測した結果は次のとおり。

| 計測対象 | PCHなしの平均 | PCHありの平均 | 差 |
|---|---:|---:|---:|
| クリーンリビルド | 227.94秒 | 245.33秒 | 17.38秒増加（7.6%） |
| `Vector3.h` 変更後の差分ビルド | 144.70秒 | 101.42秒 | 43.28秒短縮（29.9%） |

どちらもRuntimeと依存プロジェクトを含むビルド全体の経過時間。クリーンリビルドではPCHの生成が必要になるため、今回の条件では全体の時間が増えた。一方、差分ビルドでは既存のPCHが再利用され、全体の時間が短くなった。

### クリーンリビルド

Runtimeと依存プロジェクトを `/t:Rebuild` でビルドした。PCH対象の21プロジェクトでは、PCH生成を除いたC++コンパイルのCLタスク時間の合計が、平均106.21秒から60.34秒になった。一方、PCH生成には平均56.89秒かかり、生成を含めた同じ対象のCLタスク時間は平均106.21秒から117.22秒になった。

PCHありでは各回21個のPCHが生成され、合計サイズは約2.73 GiBだった。CLタスク時間はMSBuildの各タスクの経過時間の和であり、ビルド全体の経過時間やCPU時間とは異なる。

### 共有ヘッダー変更後の差分ビルド

`project/engine/core/math/vector/Vector3.h` の末尾のコメントを1行変更し、Runtimeと依存プロジェクトを `/t:Build` でビルドした。全試行でQuickForgeEngine側の同じ20プロジェクト・93個の `.obj` が更新された。

再コンパイルしたQuickForgeEngine側のCLタスク時間の合計は、平均104.41秒から60.32秒に短縮した。PCHありの試行ではPCHの使用が記録され、PCHの再生成はなかった。ビルド全体には、別途DirectXTexのシェーダーコンパイルも含まれている。

### 計測条件と結果の範囲

| 項目 | 条件 |
|---|---|
| PCHなし | `develop` / `212f86fac1460f7d47c90e9ca470b4b649610347` |
| PCHあり | `update/issues-791-pch` / `68cbd875cd66cbc3f86da2e3b842c883761a5fd7` |
| 構成 | Development / x64、C++20、最適化なし、`/Z7`、MSBuild `/m:1`、C++ `/MP4` |
| OS | Windows 25H2、ビルド26200.9974、x64 |
| CPU | 12th Gen Intel Core i5-12450H、論理12プロセッサ |
| 物理メモリ | 15.73 GiB |
| ビルド・計測先 | C:、NTFS、容量474.72 GiB |
| 電源 | Windowsの「バランス」プラン、計測時はAC接続 |
| ツール | Visual Studio 2022、MSBuild 17.14、MSVC v143 19.44、Windows SDK 10.0.26100.0 |
| 実行順 | PCHなし → あり → あり → なし |

差分ビルドは両条件で準備ビルドを行った後に計測した。クリーンリビルドのプロジェクト生成と出力の退避は計時外。両ブランチにはPCH設定のほかに `Matrix4x4` の変更もあるため、結果はPCHだけの効果を厳密に切り分けたものではない。また、各条件2回の測定で、バックグラウンド処理も動作していた。結果はこのPC・構成・変更内容での観測値として扱う。

## 制作への活用

PCHを導入すると、再利用できる差分ビルドではコンパイル時間の短縮が期待できる。一方、クリーンリビルドではPCHの生成時間やディスクへの書き込みが増える。普段の開発時のビルドと、クリーンビルドやCIの両方を測り、変更対象や構成を変えて再計測しながら導入効果を判断する。
